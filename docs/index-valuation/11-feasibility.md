# 实现可行性方案

> 结论先行：**整体可行**。3 个高风险点需要先做 Spike 验证（各 0.5~1 天），其余为常规工程量。

## 2. 技术可行性逐项

| 项 | 结论 | 依据 / 做法 |
|---|---|---|
| 复权维度迁移（最高风险） | ✅ 可行 | 加列 + 改 PK（PK 仍含分区列）+ 删 `row_hash`（quote 表无读取方）；P1 验收用 NAV 零漂移卡口 |
| 521 指数估值建模 | ✅ 可行 | 容量 125 万行/5 年，无需分区 |
| 全 A 股 ×3 复权 | ⚠️ 待验证 | 首拉 ~15000 请求；若东财限频则回退 1800 只 |
| 跨境 Binance 落库 | ✅ 可行 | Worker 抓取 → HMAC POST `/api/internal/ingest` → 幂等 upsert |
| Excel Power Query | ✅ 可行 | REST + Bearer header 可被 PQ 支持 |
| Excel 单格函数 | ⚠️ 需 VBA | 你选 Q34-A（只做 Power Query），已按此排期 |
| 分位计算一致性 | ✅ 可控 | 唯一实现 `quant/valuation.py` + 3 个金标准样本 |
| 全市场估值历史 | ⚠️ 受限 | 只能自建归档，3~6 个月后才有效 |
| 成分股业绩中位数 | ⚠️ 待补 | 需东财财报接口，放 P3 |

## 3. 必须先做的 3 个 Spike（共 2 天）

| # | 目标 | 方法 | 通过标准 | 失败后的降级 |
|---|---|---|---|---|
| S1 | 全 A 股三复权日增量耗时 | 取 300 只样本跑一个完整增量 | ≤ 15 分钟 | 回退 1800 只（Q17 预案） |
| S2 | Excel Power Query 带 Bearer 头拉 5 万行 | 本地起 FastAPI + PQ 实测 | ≤ 30 秒，无截断 | 改 CSV 下载 + 分段 |
| S3 | Cloudflare Worker → 广州 API 回传 | 最小 Worker 打 mock 接口 | 端到端 < 2s，幂等键生效 | 改 Vercel Cron 或服务器直连代理 |

## 5. 结论

- P0 的全部技术前提已被实测验证（平安接口、迁移路径、Timescale 约束）；
- 真正的不确定性集中在 **S1（全 A 抓取耗时）** 与 **S3（跨境链路）**，两者都有明确降级方案；
- 建议先跑 S1/S2/S3 再做 P0 编码，避免返工。
