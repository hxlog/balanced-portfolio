# 18 · 指数估值工作台重构方案（先行版）

> 2026-11-15 · 针对用户 6 条反馈的根因分析、F9 研究、数据能力盘点、重构信息架构与 3 套 demo。

## 一、逐条回应你的 6 个问题（含实测根因）

### 1. 全市场估值「样本积累中」+ PE 分位 50%
- **根因**：`bp_market_valuation_daily` 只有 **1 个交易日**（2026-11-14，东财截面快照），分位在单日样本上无法计算，代码退化为 50%。这是**假分位**，不是真实数据。
- **修复方向**：全市场卡片改为「最新 PE/PB 值 + 真实历史分位」，分位用**中证全指（000985）等宽基的 5 年估值序列**做代理；东财截面数据保留为「今日截面」，逐日积累 ≥60 日后自动切换为真实分位并显示进度（1/60）。
- 顶部「PE / PB 分位、股息率与风险溢价 · 521 只指数」长文案删除。

### 2. 估值分位分布图无用
- **替代方案**：改为 3 张真正能回答问题的图：① 全市场/宽基 PE-Band（带均值±σ 虚线 + 当前点）；② 板块估值热力图（分位）；③ 估值-盈利四象限（PE 分位 × 盈利增速/ROE）。

### 3. 全市场卡片都用中位数不对
- 你判断正确。卡片应展示**最新 PE/PB 绝对值 + 历史分位**（etf.run 的做法），中位数/等权只作为 table 里的截面统计口径之一。

### 4. 指数列表：缺多窗口 PB/PE 分位、空值、行业筛选、无用「估值」按钮
- 数据审计：PE 458 只 / PB 470 只 / 股息率 471 只 / ERP 471 只有序列，但**只从 2021-11 开始（约 5 年）**，没有 10 年。
- 空值来源：估值序列缺失的 63/51 只指数（多为 2021 后新增/海外指数）、行情只覆盖 452/521。**规则**：样本不足显示「—」并给 tooltip 说明原因，不允许出现假 50%。
- 行业筛选为空：`index_type` 只有宽基/主题/策略，缺「行业」分类 → 需补行业分类字段（按中证/申万行业映射）。
- 「估值」按钮：删除，整行点击进入详情。

### 5. 详情页缺披露日期、指标/窗口/标准差筛选、指数简介、数据利用率低
- 成分披露日：当前成分权重来自中证 OSS `closeweight` 文件，日期为 **2026-11-13/14**，页面必须显示该日期。
- 平安详情 API 里有 `indexIntro` 字段，但入库时未保存 → 需新增 `bp_index_master.intro` 并回填。
- 筛选联动：指标（PE/PB/股息率/ERP）× 统计口径（分位带 / 1σ / 2σ / 3σ）× 窗口（1/3/5/10Y/全部）→ 图表虚线、关键指标、成分排序全部联动。
- PCF：当前无数据（需指数级现金流），见待确认问题 Q5。

### 6. 加密货币功能没上线
- 实测：`/crypto` 有 BTC 相关性（28,304 行，最新 11-13）；`/crypto-futures` 有 30 合约、1,229 条 5 分钟快照（最新 17:30Z）。
- 但页面大量「样本」标记（分位需历史，5 分钟数据才积累 1 天）→ 看起来像没上线。
- **修复方向**：a) 回补 Binance 历史（klines 长期、资金费率/OI 30 天）；b) 无历史的模块改为「实时指标 + 积累进度」而不是假分位；c) 把两个 crypto 页面入口与数据状态做清楚。

## 二、F9 研究：值得借鉴什么

> 来源：Wind/Choice/iFinD 公开使用手册与产品介绍（见文末参考链接），以下为行业通用的 F9 信息架构。

| 模块 | F9 做法 | 我们的可落地版本 |
|---|---|---|
| 估值分析 | PE/PB/PS/PCF/EV-EBITDA 历史 Band + 分位 + 分位带/标准差带 + 行业对比 | **核心模块**：PE/PB/股息率/ERP × 分位/1-3σ × 1/3/5/10Y |
| 盈利预测 | 一致预期（营收/净利/EPS 增速） | 暂缺数据源 → 路线图（可先用指数 EPS = 点位/PE 反推） |
| 行业对比 | 同行业估值矩阵/排名 | 用申万一级行业 + 521 指数做行业估值矩阵 |
| 财务分析 | 三大报表、杜邦、成长/盈利/偿债 | 指数级：ROE=PB/PE、EPS 序列、盈利质量 |
| 股东与资金 | 股东结构、机构持仓、资金流向 | 暂缺 → 用 ETF 份额/规模变化替代 |
| 事件日历 | 分红、调样、解禁、财报 | 指数调样日、成分披露日、分红日（有数据就可做） |
| 数据透明 | 数据来源、口径、更新时间 | 每个图表标注来源与截止日（必做） |

**结论**：F9 的价值在于「同一指标 × 多口径 × 多窗口 × 可下钻」的矩阵式浏览。我们不需要抄它的公司财务模块，但应把**指数估值分析做到 F9 级**：多指标、多窗口、分位/标准差双模式、Band 图、行业矩阵、成分下钻、数据披露透明。

## 四、重构后的信息架构

### /valuation（总览）
1. 市场估值 4 卡：全市场 / 主板 / 创业板 / 科创板，每卡 = 最新 PE、PB、历史分位（带 sparkline）、数据状态徽章（真实/积累 1/60）
2. 图 1：全市场 PE-Band（5Y）+ 当前分位
3. 图 2：板块估值热力图（PE/PB 分位）
4. 图 3：估值-盈利四象限（PE 分位 × ROE/盈利增速）
5. 图 4：分位历史带（当前分位时间序列）
6. 指数表：筛选（指标 × 窗口 1/3/5/10Y × 类型 宽基/行业/策略/主题/全部 × 搜索）+ 列设置 + 整行进入详情

### /valuation/[code]（详情，F9 级）
- 头部：名称/代码/类型/收盘/涨跌/估值日期/数据来源/成分披露日
- 主图：Band 图（指标 × 分位/1-3σ × 窗口 全部联动）
- 子图：PE/EPS 拆解、分位水印、收益风险（年化/波动/回撤/夏普）、相关性
- 成分股表：披露日期、权重、申万行业、PE、CR10 集中度
- 跟踪基金表：规模合计、费用、跟踪误差
- 右栏：指数简介（平安回填）、关键指标卡（随筛选联动）、行业分布

### /crypto-futures 与 /crypto
- 合约看板：实时指标（OI、多空比、taker、标记价）立即有效；分位模块在数据积累 ≥30 天前显示「积累进度」而不出假数；回补 Binance 历史。
- BTC 相关性页：补图表与数据表。
