## 生产部署（P0 第一次上线）

### 事故：生产机上构建 Next.js 触发 OOM，PostgreSQL 被内核杀掉
- 现象：在 3.6GB 内存的生产机执行 `next build`（node RSS ≈1.4GB）→ kernel OOM killer 杀掉 PG 进程；`postgresql@18-main.service` 进入 `oom-kill` 失败态；随后 systemd 的 fast shutdown 卡住，DB 对外表现为 `the database system is shutting down`，站点 404/500。
- 影响时长：约 2 分钟（18:18–18:20）。
- 处置：杀掉卡住的 `pg_ctlcluster stop` → `pg_ctlcluster 18 main stop --force -m immediate` → `start` → 恢复；随后加 **2GB swap**（已写 fstab）。
- 复盘规则（新增）：**禁止在生产机直接构建前端**；必须「停服构建」或「本地/CI 构建后同步产物」。本次后续用 `NODE_OPTIONS=--max-old-space-size=1536 + swap` 成功构建，但仍应避免。

### 迁移 53 首次失败：out of shared memory
- 原因：hypertable 有 1274 个 chunk，`ALTER TABLE ... ADD PRIMARY KEY` 需要持有全部 chunk 锁，默认 `max_locks_per_transaction=64` 不够。
- 处置：`max_locks_per_transaction = 4096` + 重启 PG；重跑成功。
- 结果：`bp_index_quote_daily` 与 `bp_quote_clean` 主键均为 `(symbol, source, adjust, trade_date)`。
