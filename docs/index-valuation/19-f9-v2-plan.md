## 二、Next.js 16 / React 19 动态刷新方案（skill 研究结论）

加载了 `next-cache-components-optimizer` skill，核心结论：
1. **静态 shell 必须先到**：任何依赖请求的参数都应放进 Suspense 边界之后，骨架先出、数据流式补。
2. **切换筛选应改为 URL 状态 + 服务器组件**：`?window=5y&metric=pe_ttm` 由 server component 读取，客户端按钮只做 `router.replace(..., {scroll:false})`；Next 的 PPR 会先提交外壳，再流式替换对应 Suspense 边界的内容，避免「切换后仍显示旧数据」。
3. **缓存标签一致性**：`cacheLife("hours")` 必须与 `revalidateTag("valuation","hours")` 的 profile 一致（现有代码已对齐）。
4. **客户端交互用 `useTransition`**：本页大量客户端状态（搜索/排序/列设置）保留客户端；涉及服务端数据（窗口/指标）用 transition + pending 骨架，禁止在 pending 期间展示旧数值。
5. **loading.tsx / 局部 Suspense**：为行业热力、估值矩阵、指数表分别设置骨架（按区块），而不是整页 spinner。
6. **回归测试**：skills 建议用 `@next/playwright` 的 `instant()` 写「壳立即出现、数据后到」的回归用例；本项目测试栈是 vitest，先以截图 + 手动验证为准，后续可补 Playwright。
