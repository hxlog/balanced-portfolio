## 2. 工作方式（TDD + 分批）

```
每个任务：写失败测试 → 跑（红）→ 最小实现 → 跑（绿）→ 重构 → 提交 → 记账             
每 3~5 个任务：全量 pytest / npm test / build，跑一次验收子集                            
每期结束：完整验收（13 号文档命令清单）→ 代码审计（14 号文档）→ 部署 → Go/No-Go          
```

- **账本（ledger）**：`docs/index-valuation/ledger/` 下按日期记录每个任务的「做了什么/为什么/测试证据/踩坑」；跨会话不断档。
- **裁决（Ruling）**：遇到规格未覆盖的取舍，直接决定并写入账本（附代价），不阻塞等确认；但**不可逆/安全敏感/跨环境副作用**三类必须停下来问。
- **不做的事**：不跳过失败测试直接写实现；不为了过测试改断言；不在未跑全量测试时宣布完成。

## 3. 分支与提交

| 项 | 规则 |
|---|---|
| 分支 | 每期一个 `feature/pX-<name>`；P0 之前先 `chore/baseline` 打底 |
| 提交粒度 | 一个任务一次提交；消息用仓库风格（简短祈使句中文，如「新增估值分位预计算」） |
| 合并 | 每期验收通过后合并回 `main`；冲突就地解决并记账 |
| 禁止 | 不 force-push；不改已应用迁移编号；不提交 `.env`/密钥 |

## 4. 质量门禁（8 道，全部通过才允许部署）

1. `python -m pytest bp_api/tests -q` 0 failed 且用例数不减；
2. 变更相关测试全绿（新增功能必须有测试）；
3. `cd web && npm test` 全绿；
4. `cd web && npm run typecheck` exit 0；
5. `cd web && npm run build` exit 0；
6. 迁移脚本连跑 3 次 exit 0 且行数不变；
7. 冒烟：`python -m bp_ingest --help`、`python -c "from bp_api.main import app; print(len(app.routes))"`；
8. 密钥未入库（`git grep -i` 扫一遍新增文件）。

## 5. 部署流程（可在 DB 通、SSH 未通的情况下分步执行）

```
1. 迁移：python scripts/apply_migration.py 5x_xxx.sql      # 走 psycopg 直连，幂等，先 pg_dump 备份关键表
2. 后端：rsync 代码 → pm2 restart bp-api（SSH 恢复后）
3. 前端：本地 npm run build → 产物同步 → pm2 restart bp-web
4. 冒烟：curl 健康检查 + 关键页面 200 + API 样例
5. 缓存：POST /api/revalidate/<tag> 触发 Next 失效
6. 观察：30 分钟看错误日志与数据完整率；异常按回滚脚本执行
```

**回滚**：迁移只做加法（加列/加表），回滚=回滚代码；如需删列，先确认无读路径。

## 6. 并行策略

| 工作类型 | 谁做 |
|---|---|
| 数据源探索、DDL 设计、迁移、集成、部署、验收 | 主控 |
| 独立模块实现（如加密 ETL、API 端点、前端页面） | 子代理并行，写入范围互不重叠 |
| 代码审计 | 独立子代理（fresh context）按 14 号文档审 |
| 用户决策 | 只在不可逆/安全/方向性问题时提问 |
